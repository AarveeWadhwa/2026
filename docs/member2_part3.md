# Member 2 — Part 3: Tender assessment integration pipeline

## Purpose
Connect Member 1's `TenderIntelligenceAgent` JSON envelope to Member 2's eligibility and document-compliance checks. The pipeline accepts multiple tender extraction results and returns one combined assessment report.

## Files added
- `backend/services/tender_assessment_pipeline.py`: adapter/orchestrator that assesses a single extraction, list, or Member 1 envelope containing `results`.
- `backend/agents/tender_assessment_agent.py`: command-line interface for company and tender JSON files.
- `tests/test_tender_assessment_pipeline.py`: integration contract tests for Member 1's output shape, deadline discrepancy, missing source documents, and invalid payloads.

## Run
```bash
python3 -m backend.agents.tender_assessment_agent \
  --company data/sample_company.json \
  --tenders outputs/tender_intelligence.json \
  --output outputs/member2_assessment.json
```
The `--tenders` file should be generated by Member 1's `backend.agents.tender_intelligence_agent` workflow.

## Output
- `results`: one readiness report per tender, including eligibility, compliance, action items, discovery metadata, and source cross-checks.
- Results are ordered by preliminary status and eligibility score.
- Catalogue/document deadline discrepancies create a high-priority human-review action.
- Missing/unprocessable tender documents are not silently treated as successful extractions.

## Limits
This pipeline consumes supplied JSON; it does not scrape portals or monitor new tenders. Scores and status labels are decision-support indicators only. Human reviewers must confirm source clauses, document authenticity and expiry, official deadlines, and the latest corrigenda.
